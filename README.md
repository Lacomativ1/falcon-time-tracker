# Рабочее время

Небольшое локальное веб-приложение для учёта рабочего времени сотрудников. Подготовлено как тестовое задание Falcon AI. В демонстрации используются только вымышленные данные.

**Для проверяющего:** ссылка на GitHub открывает исходники и эту инструкцию. Работать с приложением можно после [установки из свежей копии](#установка-из-свежей-копии-проекта) и запуска на своём компьютере по адресу [http://127.0.0.1:5000](http://127.0.0.1:5000). Этот адрес доступен только на компьютере, где запущен сервер. Публичного онлайн-демо пока нет; по условиям задания оно необязательно.

## Возможности

- Добавление сотрудников, в том числе с одинаковыми именами: различаются по ID.
- Запуск задачи с описанием и живым счётчиком, остановка и просмотр записей.
- Один активный таймер у каждого сотрудника; разные сотрудники работают одновременно.
- Безопасная обработка повторного старта и повторной остановки.
- Сохранение сотрудников, записей и активных таймеров при перезапуске.
- Отчёт за включительный календарный период по одному или всем сотрудникам, отдельные итоги и нулевые результаты.
- Учёт только пересечения задачи с выбранным периодом, включая задачи через полночь.
- Русский адаптивный интерфейс. Основные формы работают без JavaScript.

Работодатель требует сотрудников, таймеры, отчёты, сохранение данных, проверки и описание применения ИИ. UTC, Asia/Dushanbe, CSRF и правила пересечения периода — дополнительные решения, уточняющие поведение приложения.

## Стек и окружение

Python, Flask, встроенный модуль SQLite, Jinja/HTML, CSS и небольшой JavaScript. pytest используется для проверок, tzdata — для поддержки часовых зон в Windows. Отдельный сервер базы, сборка интерфейса, внешние сервисы и API-ключи не нужны.

Проверенная версия Python: **3.12.14**. Используйте Python 3.12 или новее; фактическая проверка выполнена на 3.12.14. Установленные и проверенные версии пакетов закреплены в `requirements.txt`. Для первой установки нужен интернет, дальнейшая работа автономна.

### Настройки и хранение данных

Обязательных настроек нет. При первом запуске автоматически создаются:

- `instance/timekeeper.sqlite3` — локальная база;
- `instance/secret.key` — случайный секрет подписи сессии и CSRF.

Путь рассчитывается относительно `app.py`, поэтому запуск из другой папки терминала не создаёт вторую случайную базу. Существующие таблицы и записи не стираются. Файл базы и секрет остаются после остановки сервера. Папка `instance/` исключена из Git. Перед переносом базы остановите сервер и скопируйте её файл.

При первом запуске секрет сначала полностью записывается во временный файл, затем публикуется атомарно через жёсткую ссылку, без перезаписи ключа другого процесса. Файловая система должна поддерживать жёсткие ссылки (например, NTFS, APFS или ext4). Если существующий `secret.key` пуст или повреждён, запуск прекращается с объяснением; файл не затирается. Восстановите его из копии либо переименуйте, чтобы сгенерировать новый. Новый ключ сбросит сессии браузера, но не удалит базу.

При необходимости задайте переменные среды **до запуска**:

```powershell
$env:TIMEKEEPER_TIMEZONE = 'Asia/Dushanbe'
# Необязательно: секрет можно задать извне вместо локального secret.key.
# $env:TIMEKEEPER_SECRET_KEY = '<ваш случайный секрет>'
.\.venv\Scripts\python.exe app.py
```

В macOS/Linux: `TIMEKEEPER_TIMEZONE=Asia/Dushanbe .venv/bin/python app.py`. `.env` автоматически не читается. Не помещайте секрет в исходный код или репозиторий. По умолчанию сервер слушает только `127.0.0.1:5000`, режим отладки отключён.

## Как пользоваться

1. Добавьте вымышленного сотрудника, например «Алексей Тестов».
2. Выберите сотрудника, напишите описание и нажмите «Начать».
3. Обновите страницу: активная задача останется, отсчёт продолжится.
4. Нажмите «Остановить»: задача появится в отчёте за соответствующие дни.
5. Выберите период и сотрудника либо «Все сотрудники», нажмите «Показать отчёт».

Имя: 1–100 символов, описание: 1–1000. Пробелы по краям убираются, пустые значения и нулевые символы отклоняются. Сервер повторяет проверки независимо от HTML-ограничений.

## Правила таймеров и времени

Начало и окончание задаёт сервер. Данные времени из формы игнорируются. В SQLite хранятся целые микросекунды Unix в UTC; длительность вычисляется по временным отметкам, отдельной колонки длительности нет.

Частичный уникальный индекс SQLite запрещает две строки с незаполненным окончанием для одного сотрудника. Правило действует и при одновременных запросах. Повторный старт оставляет исходное начало и описание. Остановка — условный UPDATE только активной записи; повторная остановка не меняет сохранённое окончание.

JavaScript рисует счётчик от сохранённого начала и серверного времени, но не сохраняет длительность. При перезагрузке страницы сервер рассчитывает её заново. Активная задача продолжает считаться, пока сервер выключен: завершение ещё не зафиксировано. Для остановки нужен работающий сервер.

Если системные часы сервера ушли назад, окончание ограничивается временем начала; отрицательное время дополнительно запрещено CHECK-ограничением SQLite. Точность результата зависит от корректных системных часов компьютера.

## Отчёты и календарные границы

Интерфейс и календарные даты используют **Asia/Dushanbe** по умолчанию. Зона указана на странице и может меняться переменной среды. Сохранённые UTC-отметки при смене зоны остаются теми же, календарные границы отчёта изменятся.

Обе выбранные даты включаются целиком. Внутри используется интервал:

```text
[начало первого дня, начало дня после последнего)
```

В отчёт попадают завершённые задачи. Активные показаны отдельно и добавятся в итог после остановки. Для каждой записи учитывается только время пересечения с периодом:

```text
max(0, min(конец задачи, конец периода) − max(начало задачи, начало периода))
```

Например, задача с 23:50 до 00:20 даст 10 минут за первый день и 20 за второй. Начало и окончание в таблице показывают исходные отметки, колонка «Время в периоде» — только пересечение. Задача, которая лишь касается границы периода, времени не добавляет. Настоящая задача нулевой длительности внутри периода показывается как запись с нулём.

Сумма считается в микросекундах, затем дробная часть секунды отбрасывается для отображения `ЧЧ:ММ:СС`. Часы могут превышать 24. Из-за дробных секунд сумма отображаемых отдельных строк иногда отличается от отображаемого общего итога; общий итог вычислен до округления.

Пустой отчёт показывает нулевой итог, включая сотрудников без записей. Неверные даты или обратный диапазон дают понятную ошибку без расчёта отчёта. Фильтры сохраняются при действиях с таймерами.

## Структура

```text
app.py                 маршруты, формы, CSRF, подготовка отчёта
storage.py             схема SQLite, подключение и закрытие соединения
time_utils.py          UTC, границы периода, формат длительности
templates/             HTML-шаблоны главной и ошибок
static/                стили и отображение счётчика
tests/                 автоматические сценарии
tests/test_release.py  дополнительные проверки безопасности и конкуренции
requirements.txt       закреплённые зависимости
pytest.ini             настройки pytest
README.md              запуск и правила
STUDY_GUIDE.md         объяснение и подготовка к собеседованию
SECURITY_REVIEW.md     результаты проверки перед публикацией
instance/              локальная база и секрет, исключены из Git
```

SQL параметризован, пользовательский HTML экранируется Jinja. Все изменения выполняются через POST и защищены сессионным CSRF-токеном. Соединение с базой закрывается после запроса, запись завершается транзакцией. Ограничения базы дополняют проверки сервера.

Приложение принимает только Host `127.0.0.1` и `localhost`, включая их порты. Посторонний Host отклоняется до разбора тела и CSRF. Поддельный `X-Forwarded-Host` не учитывается. Тело запроса ограничено 64 КиБ, число частей multipart-формы — 16. CSP запрещает сторонние скрипты, встраивание страницы во фрейм и внешнюю отправку форм; cookie сессии имеет HttpOnly и SameSite=Lax. Secure-cookie и HSTS не включены, поскольку локальный запуск использует HTTP.

Код, интерфейс, тесты, технический разбор и документация подготовлены с помощью **Codex в настольном приложении**. Точный идентификатор модели этой сессии не предоставлен, поэтому конкретное название модели не приписывается. Для отдельных частей использовались вспомогательные агенты Codex; основной агент интегрировал результат и выполнял проверки.

Это не утверждение о самостоятельной ручной разработке кандидатом. Также не утверждается, что кандидат уже лично проверил и понял весь код. Для самостоятельного разбора подготовлен `STUDY_GUIDE.md`; перед собеседованием стоит повторить запуск и объяснить сценарии своими словами.

## Ошибки и исправления

**Нулевой символ во вводе.** При обзоре была воспроизведена разница между проверками Python и SQLite: строка `"\0"` непустая для Python, а SQLite считает её длину нулевой. Ранняя проверка только через `strip()` и `len()` пропускала такой ввод до ограничения базы. Это могло дать ошибку сохранения имени и неверное сообщение о повторном таймере для описания. Исправление: явный запрет NUL в обоих полях до SQL. Проверка: отдельные случаи с NUL и с NUL внутри текста включены в прошедшие тесты валидации.

**Предотвращённая гонка отчёта.** Обзор выявил, что независимые чтения сотрудников и записей могли увидеть разные состояния при параллельном добавлении сотрудника и задачи. Чтение объединено явной транзакцией. Регрессионный тест в режиме WAL действительно добавляет сотрудника и завершённую запись другим соединением между чтениями и проверяет согласованный результат, а затем видимость изменения в следующем запросе. Не выдаётся за ошибку, обнаруженную обычным ручным использованием.

**Посторонний Host и обработка ошибки.** Проверка перед публикацией воспроизвела доступ к странице и созданию записи через произвольный Host. Добавлен список `TRUSTED_HOSTS`. Первые регрессионные тесты затем выявили, что обычный HTML-шаблон ошибки обращался к `url_for()` без созданного URL-адаптера. Ошибка Host теперь возвращается простым текстом и проверяется до разбора формы: в том числе при отсутствующем CSRF и чрезмерном теле. Все соответствующие тесты проходят.

**Пустой секрет при одновременном первом запуске.** Воспроизведён случай, когда второй процесс читал уже созданный, но ещё не заполненный файл ключа. Создание изменено на атомарную публикацию готового файла без перезаписи. Отдельный тест приостанавливает первый генератор и запускает второй; оба получают одинаковый непустой ключ. Повреждённый существующий ключ явно отклоняется.

UNIQUE-индекс, условная повторная остановка и UTC-арифметика были предусмотрены заранее; это предотвращённые риски. При настройке среды также пришлось перенести временные файлы в доступную папку проекта и использовать Python с pip вместо Python из PATH — это особенности среды разработки, а не ошибки предметной логики.

## Ограничения

- Локальная демонстрация на вымышленных данных, без авторизации и разделения организаций. Доступ к работающему приложению даёт доступ ко всем его данным.
- Используется встроенный сервер Flask для локального запуска. Развёртывание в интернете и реальные данные сотрудников требуют отдельной работы над доступом, HTTPS, резервными копиями и сервером приложения.
- Нет редактирования или удаления сотрудников и записей, экспорта, ролей и автоматической остановки забытых таймеров: это вне объёма задания.
- При большом количестве записей понадобятся пагинация и оптимизация отчётов. SQLite рассчитана на небольшую нагрузку записи.
- Запись и точность времени зависят от диска и системных часов компьютера. При сбое хранилища нужна диагностика, резервные копии автоматически не создаются.
- После сна компьютера обновите страницу: на некоторых платформах браузерный монотонный счётчик не учитывает сон. Серверная остановка и отчёт используют сохранённые отметки независимо от отображения.
